# ADR-008 — Adaptador YOLO (M2) y validación por dominio

- **Estado:** aceptada (2026-11-15).
- **Decisión (adaptador):** `YoloFruitDetectorAdapter` implementa `FruitDetectorPort` con: import diferido de `ultralytics`; pesos `.pt` verificados por SHA-256 con su manifiesto (`models/m2_yolo.manifest.json`, que además declara clases, imgsz e iou de NMS); imagen PIL RGB sin EXIF (Ultralytics trata los ndarray como BGR y vuelve a aplicar la orientación EXIF); `agnostic_nms=True` para no contar dos veces una cereza con estados distintos; tolerancia en la comparación de confianzas (float32); cajas recortadas y descarte de cajas vacías o no finitas; validación de clases al cargar; `Lock` alrededor de `predict`. Probado con un modelo simulado; el notebook repite la suite de contrato con los pesos reales.
- **Decisión (procedencia):** `ModeloInfo` distingue tres niveles: no validado; validado con datos reales **de otro dominio** (p. ej. test de Croppie, fotos de Uganda) → etiqueta "VALIDADO SOLO EN OTRO DOMINIO"; validado en el dominio objetivo (fotos de fincas de Norte de Santander) → sin advertencia. Solo `ml/m2_yolo/evaluar.py --final` marca el manifiesto como validado, con el ID de corrida.
- **Composición:** `SIKAFE_DETECTOR=yolo`; es el detector por defecto en cuanto existe `models/m2_yolo.manifest.json` (el sintético queda para demo, ADR-003). Si se pide YOLO y no carga, error explícito.
